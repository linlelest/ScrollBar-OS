### 一、 前期调研与技术栈选型结论
经调研当前Windows桌面增强工具（如PowerToys、TranslucentTB、StartAllBack、Windhawk）及现代UI框架生态，结合“轻量、原生、低占用、高交互响应”的核心诉求，得出以下结论：

| 维度 | 调研结论 | 选型建议 |
|:---|:---|:---|
| **运行时体积与内存** | Electron/CEF类方案空闲占用通常 >100MB，启动慢；WPF渲染管线较老；跨平台框架（Qt/Flutter）需携带完整Runtime | **`.NET 8 + NativeAOT编译`**（发布体积可压至15-25MB，空闲内存 <25MB） |
| **UI框架** | WinUI 3 (Windows App SDK 1.5+) 原生支持Windows 11 Fluent设计、Mica/亚克力材质、圆角、GPU硬件加速合成、高DPI自适应 | **WinUI 3 + Windows App SDK** |
| **系统交互能力** | 窗口枚举、Z-Order调整、工作区计算、任务栏控制需直接调用Win32 API | **`CsWin32` + `PInvoke`**（自动生成强类型Win32绑定，零额外依赖） |
| **窗口管理兼容性** | Win11多桌面/DWM合成/虚拟桌面API需特定COM接口 | `VirtualDesktopManager` COM + `Dwmapi.dll` + `User32.dll` 组合调用 |
| **托盘限制** | Win11对直接注入系统托盘有严格安全策略，易被杀软拦截 | 采用**“系统托盘白名单桥接+应用内模拟托盘”**降级兼容方案 |

**最终技术栈定稿**：
- **语言与框架**：C# 12 / .NET 8 / WinUI 3 (1.5+)
- **编译优化**：NativeAOT（AOT编译，消除JIT，提升启动速度，彻底隔离运行时依赖）
- **系统API**：CsWin32 / Microsoft.Windows.SDK.Contracts
- **架构模式**：MVVM + ReactiveUI（响应式数据绑定，确保UI与系统线程解耦）
- **数据存储**：轻量级JSON序列化（Newtonsoft.Json 或 System.Text.Json），配置热重载

### 二、 整体架构与工程化设计
系统采用**“单进程前台渲染 + 后台系统服务线程 + 虚拟工作区映射”**三层架构：

1. **UI渲染层**（前台线程）：WinUI 3 XAML驱动，负责胶囊绘制、动画、拖拽网格、悬浮提示、设置面板。启用`DispatcherQueue`确保所有UI更新在主合成线程执行。
2. **系统交互层**（后台线程池）：
   - 窗口枚举器：定时/事件驱动获取前台/后台窗口句柄、标题、图标、位置状态。
   - 硬件监控器：低优先级轮询CPU/内存/磁盘指标，结果缓存至内存字典。
   - 托盘桥接器：读取系统托盘图标缓存，过滤无效进程，转换为UI可渲染对象。
3. **状态管理层**：集中维护窗口列表、滚动阈值、拖拽组合网格状态、配置参数。采用发布-订阅模型（`IMessenger`）向UI层推送状态变更，避免轮询阻塞。

### 三、 UI/UX 详细布局与视觉规范
整体遵循**“胶囊形态、垂直轴向、极简留白、动态反馈”**的设计语言。所有元素尺寸、间距均支持DPI自适应。

#### 1. 胶囊主体（占屏幕高度33%）
- **位置与外形**：可配置靠左/靠右。宽度默认64px，圆角半径20px。背景支持纯色、渐变、Mica/MicaAlt、Acrylic四种模式（设置项控制）。
- **内部垂直分层**：
  - **上部滚动区（约70%）**：应用图标流式列表。图标默认36x36，圆角8px。悬浮时显示应用名称Tooltip（半透明黑底白字，带微阴影）。
  - **下部固定区（约30%）**：从下至上依次为：
    - `设置按钮`（锚定胶囊绝对底部，16x16齿轮图标）
    - `小组件区`（位于设置按钮正下方，采用内嵌微胶囊样式，视觉上与主胶囊无缝衔接，不突破高度限制）
    - `3个微型固定应用`（位于小组件上方，单行排列，默认12x12，悬浮放大至28x28，带弹性过渡动画）

#### 2. 滚动交互逻辑
- **慢速滚动**（阈值：200ms内累积滚动格数 ≤3）：实时切换当前聚焦窗口。不改变窗口实际位置，仅通过 `SetForegroundWindow` + `DWM缩略图预览` 提升视觉连贯性。
- **快速滚动**（阈值：200ms内累积滚动格数 >3）：触发**“列表模式”**。图标区淡出，替换为纯文本名称列表（半透明玻璃遮罩覆盖原区域）。列表支持惯性滚动，停止后高亮当前项，1秒后自动退出列表模式并聚焦对应窗口。

#### 3. 拖拽组合区
- 用户从胶囊拖出图标时，屏幕正中央浮现**“组合网格区”**（尺寸自适应屏幕70%，半透明Mica背景）。
- 网格默认显示为等分方块（仅占位符+应用图标），支持自由拖入/拖出、格间交换。数量无限制。
- 网格右下角固定显示**“应用”按钮**（圆角按钮，主色调）。点击后执行平铺算法，所有选中窗口按网格顺序等分铺满当前显示器工作区（排除系统保留区域）。

#### 4. 二级菜单（设置按钮展开）
- 展开方向：胶囊在右侧时向左滑出，胶囊在左侧时向右滑出。宽度180px，高度随内容自适应。
- 包含模块：
  - `系统托盘`：显示已桥接的托盘图标，点击恢复对应窗口。
  - `固定应用`：展示用户手动拖入/添加的快捷启动项，支持右键取消固定。
  - `关闭/隐藏`：控制菜单折叠。
- 动画：使用`SlideTransition`+`FadeIn`，时长180ms，缓动函数`CubicEaseOut`。

#### 5. 设置页面
严格限定以下6项，采用左右分栏或卡片式布局：
1. **胶囊背景颜色**：拾色器 + 透明度滑块 + 材质下拉（纯色/玻璃态/系统同步）
2. **胶囊位置**：左/右切换开关（带平滑位移动画）
3. **胶囊小组件**：开关组（日期时间、硬件信息），硬件信息默认勾选
4. **是否隐藏系统任务栏**：Toggle开关（需管理员权限时弹窗提示并引导提权）
5. **语言**：下拉选择（简体中文/English），切换后重启UI渲染层
6. **各组件大小**：滑块控制（图标尺寸、胶囊宽度、字体大小），实时预览

### 四、 核心功能实现逻辑

#### 1. 滚动状态机与窗口切换
- 记录 `MouseWheelDelta` 时间序列。计算滑动速率 `V = ΣΔ / Δt`。
- 慢速态：维护一个“虚拟焦点索引”，每次滚轮事件更新索引，调用 `EnumWindows` 匹配对应窗口句柄，执行 `BringWindowToTop`。
- 快速态：切换至文本列表容器。停止滚动后，取当前高亮项对应的窗口，执行聚焦。1.5秒后自动切回图标态。

#### 2. 硬件信息悬浮窗
- 后台线程以2秒间隔采集CPU使用率（默认展示）。数据写入 `ConcurrentDictionary`。
- 鼠标悬浮于硬件小组件时，触发 `Popup` 控件。Popup定位在按钮正上方（通过 `PopupPlacementHelper` 计算屏幕边界，避免溢出）。
- 内部显示CPU、内存、磁盘、网络四项迷你进度条。采用懒加载渲染，仅悬浮时激活采集线程。

#### 3. 平铺算法与窗口布局
- 获取当前显示器有效工作区：`SystemParameters.WorkArea` 或通过 `GetMonitorInfo` 获取。
- 根据组合区图标数量 `N`，计算行列数：优先接近黄金分割矩形（如 `cols = ceil(sqrt(N))`，`rows = ceil(N/cols)`）。
- 每个窗口分配尺寸：`W = WorkspaceWidth / cols`，`H = WorkspaceHeight / rows`。
- 遍历图标顺序，依次调用 `SetWindowPos(hwnd, HWND_TOP, x, y, W, H, SWP_SHOWWINDOW | SWP_ASYNCWINDOWPOS)`。执行前捕获原位置，支持 `Ctrl+Z` 撤销。

#### 4. 托盘与任务栏隐藏
- **托盘**：通过 `Shell_NotifyIcon` 读取已注册图标句柄，或监听 `Shell` 消息。受系统限制，采用“应用内托盘容器”+“手动添加路径/白名单”双轨制。
- **隐藏任务栏**：调用 `FindWindow("Shell_TrayWnd", null)` 获取句柄，结合注册表 `StuckRects3` 或 `SetWindowLong` 修改样式。提供“还原快捷键（Win+T）”作为安全出口。

### 五、 轻量化与性能优化策略
1. **内存与CPU控制**：
   - UI列表启用 `ItemsRepeater` 虚拟化，仅渲染可视区域内的图标。
   - 硬件监控采用事件驱动替代高频轮询，空闲时挂起线程。
   - 配置数据采用内存缓存+按需落盘（防抖写入，避免频繁IO）。
2. **渲染优化**：
   - 禁用非必要 `DropShadow`，改用 `Border` 描边+透明度模拟深度。
   - 滚动与拖拽动画启用 `CompositionAPI` 硬件加速，强制GPU合成。
   - 低配设备降级策略：检测系统性能评分，自动切换至纯色背景、关闭亚克力、简化动画。
3. **编译与分发**：
   - 启用 `PublishAot=true`，裁剪未使用IL，生成单一原生EXE。
   - 提供MSIX安装包（支持静默更新、自动关联自启动）与绿色便携包（解压即用）。
   - 启动优化：延迟加载非核心模块（如托盘桥接、平铺算法），首屏渲染目标 <300ms。

### 六、 开发实施路径与风险控制
#### 开发阶段
1. **原型验证（2周）**：胶囊UI骨架、滚动状态机、虚拟列表性能压测。
2. **核心交互（3周）**：拖拽组合网格、平铺算法、快慢滚逻辑、设置页数据绑定。
3. **系统对接（3周）**：Win32窗口枚举、任务栏隐藏/还原、托盘桥接、硬件采集。
4. **打磨与发布（2周）**：NativeAOT构建、多DPI适配、动画曲线调优、安装包集成。

#### 风险与应对
| 风险点 | 影响 | 应对方案 |
|:---|:---|:---|
| Win11 托盘API权限收紧 | 托盘图标无法完整显示 | 采用“白名单+手动添加”降级；提供应用内通知中心作为替代入口 |
| 多显示器/DPI混合环境 | 胶囊错位、平铺计算偏差 | 全面启用 `PerMonitorV2` DPI感知；工作区计算绑定当前鼠标所在显示器 |
| 任务栏隐藏导致快捷键冲突 | 系统Win键失效或AltTab异常 | 不拦截系统快捷键；隐藏仅修改视觉状态；提供显式恢复机制 |
| 快速滚动误判/卡顿 | 交互不流畅 | 引入自适应阈值算法（根据设备帧率动态调整Δt）；滚动事件合并防抖 |

### 结语
本方案以**“原生渲染、极简交互、轻量运行”**为设计基石，完全规避Web容器与虚拟化运行时，通过WinUI 3的现代化合成管线与Win32系统API的精准调用，实现任务栏/托盘的高效替代。所有交互逻辑均围绕“鼠标流式操作+视觉即时反馈”展开，设置项严格收敛于6项核心参数，符合实用主义美学。按此架构推进，可在保证系统级稳定性的前提下，达成 <30MB 内存占用、 <0.5s 冷启动、60FPS 流畅交互的轻量化目标。
